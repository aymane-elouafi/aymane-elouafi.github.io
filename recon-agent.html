An agentic recon & footprinting assistant for authorized network pentesting
(HTB labs, internal/external engagements). You give it a scope; it scans in-scope
hosts, enumerates each service, looks up public exploits for the versions it finds,
and writes a report. It runs its tools inside a locked-down Kali container and uses
a local LLM.

Authorized use only. The agent refuses any target not in scope.yaml, and the
container firewall physically drops traffic to anything out of scope. It performs
recon and enumeration only — it does not run exploits. Exploit matches in the
report are leads for your own manual, authorized follow-up.

How it works

Planner (rules + optional LLM advice)
  → approval gate (autonomy tier)
    → Sandbox: validate binary + scope + no shell metachars
      → Kali container (firewall = scope only)
        → parse output → state map (SQLite) → findings
          → Markdown report

The design is deliberately not "let the model run commands". A small local model
(tested: a 9B on an 8 GB GPU) is not reliable enough to decide what is vulnerable, so:

  • Discovery, per-service enumeration and exploit lookup are rule-based — they always run.
  • The LLM only advises (suggests at most one extra step from the fixed tool list,
    validated against scope before it can run) and helps write up results.
  • Safety is structural, not prompt-based: an allowlist of binaries, scope checks on
    every IP in every command, no shell (argv only), and a container that can't route off-scope.

Setup

cd recon-agent
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
docker build -t recon-agent-kali:latest kali/      # one-time (large)
python -m agent.cli doctor                          # check prerequisites

Point an OpenAI-compatible local LLM at the defaults (LM Studio on :1234), or set
RECON_LLM_URL / RECON_LLM_MODEL. The agent runs without an LLM too (rule-based only).

Run

cp config/scope.example.yaml config/scope.yaml      # then edit targets + authorized_by
python -m agent.cli run --scope config/scope.yaml   # CLI, asks before gated steps

Web UI (start runs, watch live, approve steps, read the report):

uvicorn web.app:app --host 127.0.0.1 --port 8700
# open http://127.0.0.1:8700

Scope file

See config/scope.example.yaml. Key fields: targets
(CIDRs/IPs), exclude, autonomy (low/medium/high — how much runs without
asking; exploitation is never auto), and limits.

Autonomy tiers

Tier Tools Runs
low nmap, host_discovery, whatweb, smb_enum, smb_shares, nmap_nse, dns_axfr, searchsploit auto at autonomy ≥ low
medium ffuf directory brute-force, nikto auto at autonomy ≥ medium, else asks
shell run_command (ad-hoc command, allowed binary) always asks — never auto
exploit msf_exploit (validate a known vuln with Metasploit, confirm RCE) always asks (approval button) — never auto

Knowledge base + web research (the "brain")

Before enumerating a service the planner consults a persistent knowledge base
(knowledge table). On a miss, if research is enabled it looks the service up on the
web (agent/research.py: SearXNG → page extraction → local-embedding ranking) and
saves what it learns as unverified, promoting entries that actually produce
findings and demoting ones that don't — so the agent improves across runs. Web text is
untrusted: it can only select from a fixed technique vocabulary and is mapped to the
tool allow-list; it is never turned into a command. Set research.offline_only: true
to disable all web access (and for reproducible benchmarks).

Restricted shell

run_command lets the agent (via its LLM advisor) propose a single ad-hoc command for
a case the typed tools don't cover — a specific NSE script, an smbclient action,
curling a discovered path. It goes through the exact same gate as everything else
(binary on the allow-list, every IP in scope, no shell metacharacters — commands run
argv-style, never through a shell) and it always requires operator approval.

Deep footprinting + exploit validation

Each service is enumerated with several tools, not one (e.g. a web port runs
whatweb + directory brute-force + NSE http-* scripts + nikto; SMB runs enum4linux-ng

  • anonymous share listing + smb-vuln-*), and the knowledge base / web research can add
    more. Where a service fingerprint matches a curated vulnerability
    (agent/exploits.py, e.g. vsftpd 2.3.4, Samba 3.0.20 usermap_script, distccd,
    UnrealIRCd), the agent can validate it: it runs the matching Metasploit module via
    kali/msf-run.sh and proves code execution by running id/uname on any session it
    opens — a confirmed finding, not a guess.

This is for authorized labs only. Exploit validation is tier exploit, which
never runs automatically: every attempt waits in the approval queue (a red card in
the web UI) until you approve it, and only ever targets an in-scope host. The scope
firewall + command-level scope check still apply, so the exploit can only reach the
authorized target. host_network: true in a scope lets the container reach a VM on your
own machine's networks directly (firewall skipped there; scope still enforced in-tool).

Layout

agent/        scope, sandbox, container, store, tools, parsers, planner, research, llm, engine, cli
kali/         Dockerfile + firewall.sh + entrypoint.sh (the locked-down toolbox)
web/          FastAPI app + single-page UI
config/       scope files
data/         SQLite DB (state + audit log + knowledge base) + per-run raw tool output
reports/      generated Markdown reports
tests/        logic tests (no Docker/LLM/network): python tests/test_core.py (also test_research, test_kb, test_shell)
